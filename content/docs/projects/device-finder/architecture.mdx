# Architecture & Internals

Device Finder is built with Rust, using a modular architecture that separates platform-specific detection from the presentation layer.

## Project Structure

```
device-finder/
├── Cargo.toml              # Package manifest
├── src/
│   ├── main.rs            # CLI entry point
│   ├── lib.rs             # Core types and orchestration
│   ├── cli.rs             # Command-line argument parsing
│   ├── tui.rs             # Terminal UI implementation
│   ├── ios.rs             # iOS detection via simctl
│   ├── android.rs         # Android detection via adb
│   └── web.rs             # Web detection
└── README.md
```

## Core Design Principles

### 1. Platform Abstraction

Each platform implements the `DeviceDetector` trait:

```rust
trait DeviceDetector {
    fn detect(&self) -> Result<Vec<Device>>;
    fn platform(&self) -> DevicePlatform;
}
```

This allows the main logic to treat all platforms uniformly while each implementation handles its specifics.

### 2. Unified Device Model

All devices, regardless of platform, are represented as:

```rust
struct Device {
    id: String,                    // Unique identifier
    name: String,                  // Display name
    platform: DevicePlatform,      // iOS, Android, Web
    device_type: DeviceType,         // Simulator, Emulator, Physical, Container
    status: DeviceStatus,            // Connected, Shutdown, etc.
    udid: Option<String>,          // iOS UDID
    os_version: Option<String>,    // OS version string
    model: Option<String>,         // Device model
    details: HashMap<String, String>, // Platform-specific extras
}
```

### 3. Command Execution

Platform detection relies on external tools:

| Platform | Tool | Purpose |
|----------|------|---------|
| iOS | `xcrun simctl` | List simulators and runtimes |
| Android | `adb devices -l` | Physical devices |
| Android | `emulator -list-avds` | Virtual devices |

## Detection Implementation

### iOS Detection

**Command:** `xcrun simctl list devices available --json`

**Parsing Strategy:**
1. Execute simctl with JSON output for structured data
2. Parse runtime headers (e.g., "iOS 18.4") to extract OS version
3. Parse device entries: `Name (UDID) (Status)`
4. Map simctl status to DeviceStatus enum
5. Extract model from device type string

**Status Mapping:**
- `Booted` → Connected
- `Shutdown` → Shutdown
- Others → Unknown

**Challenges:**
- Output format varies between Xcode versions
- Runtime information is contextual (appears before devices in list)
- UDID format changed in newer iOS versions

### Android Detection

**Commands:**
- `adb devices -l` - Physical devices
- `emulator -list-avds` - Virtual devices

**Physical Device Parsing:**
```
List of devices attached
ABCD1234    device product:model device:model transport_id:1
```

**Emulator Parsing:**
Simple list of AVD names, one per line.

**Status Detection:**
- Device appears in `adb devices` → Connected
- AVD exists but not in adb list → Shutdown

**Challenges:**
- ADB daemon may not be running (auto-started on first call)
- Emulator binary location varies by installation method
- No built-in way to get OS version for shutdown emulators

### Web Detection

**Current Implementation:** Placeholder with static browser list.

**Future Enhancement:**
- Detect installed browsers via OS-specific methods
- List Docker containers with web services
- Support for browser versions and profiles

## TUI Architecture

### State Management

The TUI uses a centralized state struct:

```rust
struct AppState {
    devices: Vec<Device>,           // Cached device list
    selected: usize,                // Current selection index
    scroll_offset: usize,           // Viewport scroll position
    filter_platform: Option<DevicePlatform>,
    sort_by: SortBy,
    sort_asc: bool,
    scroll_state: ScrollbarState,
}
```

### Rendering Pipeline

1. **Event Loop** (50ms poll)
   - Check for keyboard/mouse input
   - Update selection state
   - Trigger redraw on changes

2. **Draw Phase**
   - Split terminal into layout chunks
   - Filter and sort devices
   - Render table with visible slice
   - Update scrollbar position
   - Render details panel
   - Render status bar

3. **Optimization**
   - Only visible rows are rendered (viewport culling)
   - State changes trigger selective redraw
   - Scrollbar state updated incrementally

### Layout Constraints

```rust
constraints: [
    Constraint::Length(1),      // Header
    Constraint::Min(0),         // Table (expands)
    Constraint::Length(4),      // Details panel
    Constraint::Length(1),      // Status bar
]
```

## Error Handling

### Strategy

Uses `anyhow` for ergonomic error handling:

```rust
fn detect(&self) -> Result<Vec<Device>> {
    let output = Command::new("xcrun")
        .args(&["simctl", "list", "devices", "available"])
        .output()
        .context("Failed to run xcrun simctl")?;
    
    if !output.status.success() {
        bail!("simctl returned non-zero exit code");
    }
    
    Ok(self.parse_output(&output.stdout))
}
```

### Error Contexts

- Tool not found (xcrun, adb, emulator)
- Command execution failure
- Parse errors (malformed output)
- Permission errors

## Platform-Specific Code

### macOS Only (iOS)

```rust
#[cfg(target_os = "macos")]
mod ios {
    // iOS detection implementation
}
```

The iOS module is conditionally compiled only on macOS, but the DevicePlatform enum exists on all platforms for uniform handling.

### Cross-Platform (Android, Web)

Android detection works on macOS, Linux, and Windows. Platform-specific path handling is abstracted through environment variables (`ANDROID_HOME`).

## Performance Considerations

### Detection Speed

| Platform | Typical Time | Bottleneck |
|----------|--------------|------------|
| iOS | ~100ms | simctl JSON parsing |
| Android | ~200ms | ADB daemon startup |
| Web | ~1ms | Static list |

### Optimization Strategies

1. **Parallel Detection**: All platform detectors run concurrently (future enhancement)
2. **Caching**: Detected devices cached in TUI mode, manual refresh only
3. **Lazy Loading**: Details fetched on-demand in TUI
4. **Viewport Culling**: Only render visible table rows

### Memory Usage

Typical footprint:
- Base binary: ~2MB
- Runtime (TUI): <10MB
- Device cache: <1KB per device

## Testing Strategy

### Unit Tests

Platform parsers tested with mock output:

```rust
#[test]
fn test_ios_parse() {
    let output = r#"-- iOS 18.4 --
    iPhone 16 Pro (ABCD-1234) (Shutdown)"#;
    
    let devices = IosDetector::parse_output(output);
    assert_eq!(devices.len(), 1);
    assert_eq!(devices[0].name, "iPhone 16 Pro");
}
```

### Integration Tests

Require actual platform tools:
- iOS: Requires macOS with Xcode
- Android: Requires Android SDK

Run with: `cargo test -- --ignored`

## Future Architecture

### Planned Enhancements

1. **Async Detection**
   - Use `tokio` for concurrent platform detection
   - Timeout handling for slow commands

2. **Caching Layer**
   - Persist device list to disk
   - Cache OS version lookups
   - Invalidate on tool version changes

3. **Plugin System**
   - Allow custom device detectors
   - Third-party platform support

4. **Remote Devices**
   - SSH-based detection for remote build machines
   - CI/CD integration for device farms

### Extensibility Points

Adding a new platform requires:
1. New `DevicePlatform` variant
2. Implement `DeviceDetector` trait
3. Add to detection orchestrator
4. Update TUI color mapping
