PyTorch Basics

Dynamic computational graphs, eager execution, and a Pythonic API. The research standard for deep learning.

Why PyTorch?

PyTorch is preferred by researchers and increasingly by practitioners because of its:

Key Advantages
  • Dynamic graphs: Build computation graphs on-the-fly during forward pass. Easy to debug, supports conditional logic.
  • Eager execution: Code runs immediately (like NumPy), not deferred. Intuitive for researchers.
  • Pythonic: Feels like normal Python. Uses standard Python control flow.
  • Strong ecosystem: Hugging Face (NLP), PyTorch Lightning (training framework), TorchVision (computer vision).
  • Community: Most cutting-edge research uses PyTorch.
Installation & Core Concepts
  • Install: pip install torch torchvision
  • Tensors: PyTorch's main data structure (like NumPy arrays, but GPU-enabled).
  • x = torch.randn(3, 4) — create tensor. x = x.to('cuda') — move to GPU.
  • Autograd: Automatic differentiation. x.requires_grad = True — track gradients.
  • y = x.sum() — forward pass. y.backward() — compute gradients. Access via x.grad.
  • nn.Module: Base class for all models. class Model(nn.Module): def forward(self, x): — define architecture.

Training Loop Pattern

1
Create model, optimizer, loss: model = MyModel() | optimizer = torch.optim.Adam(model.parameters(), lr=0.001) | loss_fn = nn.CrossEntropyLoss()
2
Forward pass: output = model(x)
3
Compute loss: loss = loss_fn(output, y)
4
Backward: optimizer.zero_grad() (clear old gradients) → loss.backward() (compute new gradients)
5
Update: optimizer.step() — update parameters
Common PyTorch Gotchas
  • Forget .backward(): If loss doesn't decrease, you probably didn't call backward(). No gradients → params don't update.
  • Forget optimizer.zero_grad(): Gradients accumulate by default. zerograd() at each step.
  • Model in eval mode: model.eval() before inference. Disables dropout, batch norm. Otherwise predictions are stochastic.
  • Dimensions matter: Matrix shapes must align. Common error: batch size mismatches.

Keras & TensorFlow

High-level API for deep learning. Keras (now part of TensorFlow) prioritizes easy APIs and production deployment.

GraphsDynamic (eager)Static (XLA, TPU optimized)
ResearchDominantGrowing
ProductionGood (TorchScript)Excellent (TF Serving)
Mobile/EdgeTF Lite betterTF Lite native
Installation & Quick Model
  • Install: pip install tensorflow (includes Keras)
  • from tensorflow import keras | from tensorflow.keras import layers
  • Sequential model: model = keras.Sequential([ layers.Dense(64, activation='relu', input_shape=(784,)), layers.Dropout(0.2), layers.Dense(10, activation='softmax') ])
  • model.compile(optimizer='adam', loss='sparse_categorical_crossentropy', metrics=['accuracy'])
  • model.fit(X_train, y_train, epochs=10, validation_data=(X_val, y_val))
Why Keras?
  • Simple API: ML engineers (less deep learning experience) prefer Keras's simplicity.
  • Built-in utilities: Data pipeline, callbacks, early stopping, checkpointing — all in one place.
  • Production ready: TensorFlow's deployment pipeline (TF Serving, TF Lite) is mature.
  • But: Less flexible than PyTorch for custom dynamics. Harder to debug.

Functional API for Complex Models

Sequential API only handles linear stacks. For branching, merging, skip connections, use Functional API:

Example: Multi-Input Model
  • input1 = keras.Input(shape=(32,))
  • x1 = layers.Dense(64, activation='relu')(input1)
  • input2 = keras.Input(shape=(64,))
  • x2 = layers.Dense(64, activation='relu')(input2)
  • concatenated = layers.concatenate([x1, x2])
  • output = layers.Dense(1)(concatenated)
  • model = keras.Model([input1, input2], output)

Convolutional Neural Networks (CNNs)

The standard for image data. Learns hierarchical spatial features via convolution.

Convolution Operation

Convolve a small kernel (filter) across the image. Each position computes a dot product: C[i,j] = sum(Input[i:i+k, j:j+k] * Kernel). Output is a feature map.

Why Convolution?
  • Parameter sharing: Same weights applied at every spatial location. Massive reduction in parameters.
  • Local connectivity: Each neuron connects only to nearby pixels, not globally. Respects spatial structure.
  • Translation invariance: Features learned in one location transfer to others.
  • Hierarchy: Early layers learn edges, middle layers learn shapes, deep layers learn objects.

Typical CNN Architecture

1
Convolutional blocks: Conv2d → ReLU → MaxPooling (repeat 3–5 times)
2
Flatten: Reshape spatial maps to 1D vector
3
Fully connected: Dense layer(s) for classification

Pre-trained Models (Transfer Learning)

For most image tasks, start with a pre-trained model (ImageNet) rather than training from scratch:

Transfer Learning Pattern
  • from torchvision import models
  • model = models.resnet50(pretrained=True) — download pre-trained weights
  • model.fc = nn.Linear(2048, num_classes) — replace final layer for your task
  • Freeze early layers: for param in model.conv1.parameters(): param.requires_grad = False
  • Train only the final layer (or last few) on your data.

RNNs & Transformers

Processing sequences. RNNs are classical; Transformers (attention-based) are the modern standard.

Recurrent Neural Networks (RNNs)

Process sequences one token at a time, maintaining a hidden state that accumulates information:

h_t = tanh(W_h · h_{t-1} + W_x · x_t + b)
y_t = W_o · h_t + b_o
RNN Variants
  • Vanilla RNN: Simple but suffers from vanishing/exploding gradients over long sequences.
  • LSTM (Long Short-Term Memory): Gates (input, forget, output) control information flow. Much better on long sequences.
  • GRU (Gated Recurrent Unit): Simpler LSTM (2 gates instead of 3). Often comparable performance, faster.
PyTorch LSTM Example
  • self.lstm = nn.LSTM(input_size=100, hidden_size=128, num_layers=2, batch_first=True)
  • output, (h_n, c_n) = self.lstm(x) — (seq_len, batch, hidden_size)
  • h_n is the final hidden state (use for classification)
  • output is all hidden states (use for sequence-to-sequence tasks)

Transformers & Attention

Transformers replace RNNs with self-attention: each token directly attends to all other tokens in parallel. No recurrence → much faster training.

Key Idea
  • Self-Attention: For each query token, compute a weighted sum of values from all keys. Weights (attention scores) are learned.
  • Parallel processing: All tokens processed simultaneously, not sequentially like RNNs.
  • Positional encoding: Add position information (sin/cos encodings) because attention is invariant to position.
  • Multi-head attention: Multiple attention heads in parallel, each attending to different features.
Pre-trained Transformers: Use Hugging Face
  • Install: pip install transformers torch
  • from transformers import AutoTokenizer, AutoModel
  • tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
  • model = AutoModel.from_pretrained("bert-base-uncased")
  • inputs = tokenizer("Hello world", return_tensors="pt")
  • outputs = model(**inputs)

Reinforcement Learning

An agent takes actions to maximize cumulative reward. Trial-and-error learning in interactive environments.

Core Concepts

Markov Decision Process (MDP)
  • State (s): Environment configuration.
  • Action (a): Agent's choice.
  • Reward (r): Immediate feedback from environment.
  • Transition: P(s'|s,a) — probability of next state.
  • Policy (π): Agent's decision rule: π(a|s) = probability of action a in state s.
  • Value function V(s): Expected cumulative future reward from state s.

Two Main Approaches

Value-Based (Q-Learning)

Learn Q(s,a) = expected reward of taking action a in state s. Greedy policy: select argmax_a Q(s,a).

Policy-Based (Policy Gradient)

Learn π(a|s) directly. Use gradient of expected reward w.r.t. policy parameters.

Q-Learning (Tabular)

For small, discrete state/action spaces. Update Q-values iteratively:

Q(s, a) ← Q(s, a) + α[r + γ·max_a' Q(s', a') − Q(s, a)]
// α = learning rate, γ = discount factor (0 < γ < 1)
Policy Gradient (Deep RL)
  • from stable_baselines3 import DQN, PPO — high-level library
  • env = gym.make('CartPole-v1') — OpenAI Gym environment
  • model = PPO('MlpPolicy', env).learn(total_timesteps=10000)
  • PPO (Proximal Policy Optimization) is state-of-the-art for continuous control.
RL Challenges
  • Sample inefficiency: Requires millions of interactions with the environment. Hard with real-world systems.
  • Exploration vs exploitation: Balance between trying new actions (explore) and repeating good ones (exploit).
  • Non-stationarity: As agent learns, environment appears non-stationary (policy keeps changing).
  • Use pre-built libraries (Stable Baselines, RLlib): Don't implement from scratch.

AutoML & Hyperparameter Optimization

Automating model selection and tuning. Grid search, random search, Bayesian optimization, and meta-learning.

Hyperparameter Tuning: Beyond Grid Search

Problem
  • Grid search exhaustively tries all combinations. Exponential in number of hyperparameters → infeasible.
  • Random search samples randomly. Often outperforms grid search (some hyperparams matter more than others).
  • Better approach: Use the structure of the problem. Model performance to guide search.

Bayesian Optimization

Model the relationship between hyperparameters and model performance as a Gaussian Process. Use the model to suggest promising hyperparameter combinations to evaluate next. Balances exploration vs exploitation.

Optuna (Popular BO Library)

AutoML: Automating Everything

Beyond HPO — automatically select algorithms, features, preprocessing, stacking, etc.

Popular AutoML Tools
  • H2O AutoML: Trains multiple algorithms, ensemble. Simple API.
  • Auto-sklearn: Meta-learning for algorithm selection. Learns from prior tuning.
  • TPOT: Genetic programming to optimize pipelines.
  • AutoGluon (AWS): Multilayer ensemble. Often top Kaggle solutions.
  • Ray Tune: Distributed HPO. Scales to many GPUs/nodes.

Learning Curves & Diagnostics

When to Stop Tuning
  • Log learning curves: Plot train vs val metric over tuning iterations. If flat, the search space or algorithm isn't finding improvements.
  • Diminishing returns: If best model hasn't improved in 20 trials, stop.
  • Overfitting to val set: If val metric improves but test metric plateaus, you've tuned too hard.
