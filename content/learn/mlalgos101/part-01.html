Ridge & Lasso Regression

L2 and L1 regularization: when and why to use them. The difference between shrinking and zeroing.

Ridge Regression (L2 Regularization)

Ridge smoothly shrinks coefficients toward zero without eliminating them. Use when you suspect all features are relevant but some are noisy.

Scikit-Learn Implementation
  • from sklearn.linear_model import Ridge
  • Key parameter: alpha (λ). Larger → more shrinkage. Start with alpha=1.0.
  • Usage: Ridge(alpha=1.0).fit(X_train, y_train)
  • Get coefficients: .coef_
Ridge vs Linear Regression
  • Linear Reg (OLS): minimize MSE only. No penalty for large coefficients.
  • Ridge: minimize MSE + alpha·(sum of squared coefficients).
  • Ridge trades a small increase in bias for a large decrease in variance — especially useful with multicollinearity.
  • All coefficients remain non-zero (unless alpha → ∞).

Lasso Regression (L1 Regularization)

Lasso produces sparse solutions — many coefficients become exactly zero. Automatic feature selection. Use when you suspect most features are irrelevant.

Scikit-Learn Implementation
  • from sklearn.linear_model import Lasso
  • Key parameter: alpha (λ). Larger → more coefficients driven to zero.
  • Usage: Lasso(alpha=0.1).fit(X_train, y_train)
  • Higher alpha typically needed for Lasso than Ridge for similar effect.

Ridge vs Lasso — When to Use Each

SituationRidgeLasso
Many correlated features✓ Keeps all, shrinks smoothly⚠ Arbitrarily picks one
Suspected irrelevant featuresDoesn't eliminate✓ Zeros them out
Interpretability priorityHard (many small coefs)✓ Easier (many zeros)
High-dim, few samples✓ Stable✓ Does feature selection
Critical Gotchas
  • Scale your features: Ridge/Lasso penalties treat all coefficients equally. Unscaled features with large ranges get unfairly penalized. Always standardize before fitting.
  • Lasso arbitrariness: With correlated features, Lasso arbitrarily selects one and zeros the rest. Not reproducible across runs/seeds. If you need stability, use Elastic Net.
  • alpha = 0 means no regularization — equivalent to OLS.
  • Tuning alpha: Use cross-validation. sklearn's RidgeCV and LassoCV do this automatically.

Parameter Summary

Key Hyperparameters
  • alpha: Regularization strength. Higher = more penalty. Ridge/Lasso respond differently to scale. Use CV to find optimal.
  • solver (Ridge/Lasso): For Ridge, 'auto' is fine (uses best method for your data). For Lasso, 'cd' (coordinate descent) is standard.
  • fit_intercept: Whether to fit a constant term (default True). Usually keep True.

Elastic Net

The best of both worlds: Ridge's stability with Lasso's interpretability.

The Problem Ridge and Lasso Solve Independently

Ridge Strengths

Handles correlated features gracefully. Stable coefficient estimates. Continuous shrinkage.

Lasso Strengths

Performs feature selection. Produces sparse, interpretable models. Zero coefficients clearly mean "not important".

Elastic Net combines both penalties in a weighted sum:

Loss = MSE + α·[λ·(Σ|wᵢ|) + (1−λ)·(Σwᵢ²)]
// λ ∈ [0, 1] controls mix: λ=0 is pure Ridge, λ=1 is pure Lasso
// α is overall regularization strength

When to Use Elastic Net

Elastic Net is Your Default Choice When:
  • You have many correlated features (Lasso might pick one arbitrarily, Elastic Net keeps related ones).
  • You want some feature selection but also stability — the gold standard.
  • Your data is high-dimensional with few samples — both penalties help avoid overfitting.
  • You're unsure whether Ridge or Lasso is better — Elastic Net hedges your bet.
Scikit-Learn Implementation
  • from sklearn.linear_model import ElasticNet
  • Key parameters:
  • alpha: Overall regularization strength (default 1.0).
  • l1_ratio: Mix of penalties (default 0.5). Between 0 and 1. 0 = pure Ridge, 1 = pure Lasso.
  • Usage: ElasticNet(alpha=0.1, l1_ratio=0.5).fit(X_train, y_train)

Hyperparameter Tuning Strategy

1
Start with default l1_ratio=0.5. This is usually a good middle ground.
2
Tune alpha using cross-validation. Use ElasticNetCV(l1_ratio=0.5, cv=5) to auto-tune alpha.
3
If you want more feature selection, increase l1_ratio toward 1. If you want more stability, decrease toward 0.
4
Optional: grid search both alpha and l1_ratio using GridSearchCV. Expensive but thorough.
Common Mistakes
  • Forgetting to scale features. L1 and L2 penalties treat all coefficients equally — large-scale features get unfairly penalized.
  • Using high alpha for high-dimensional data. Too much regularization → high bias. Start alpha=1.0, decrease if train error is too high.
  • Not understanding l1_ratio. It's not the "mix" in the intuitive sense — it's the ratio in the loss function. Experiment with values: 0.1, 0.5, 0.9.

Logistic Regression

Classification via the sigmoid function. Interpretable, fast, and the baseline for any classification problem.

Binary Classification

Logistic regression outputs probabilities P(y=1) directly. Use the sigmoid function to squeeze a linear combiner into [0, 1]:

P(y=1|x) = σ(wᵀx + b) = 1 / (1 + e^(−wᵀx − b))
// Threshold at 0.5: if P > 0.5, predict class 1; else class 0
Scikit-Learn Implementation
  • from sklearn.linear_model import LogisticRegression
  • Key parameters:
  • C: Inverse regularization strength (default 1.0). Larger C = less regularization = more complex model.
  • penalty: 'l2' (Ridge, default), 'l1' (Lasso), 'elasticnet', or 'none'.
  • solver: Algorithm ('lbfgs' for small data, 'liblinear' for binary, 'saga' for large scale).
  • class_weight: 'balanced' to handle class imbalance automatically.
  • Usage: LogisticRegression(C=1.0, penalty='l2', solver='lbfgs').fit(X_train, y_train)

Multiclass Extension: One-vs-Rest

For K classes, sklearn trains K separate classifiers — one for each class vs. all others. Then takes the argmax.

Key Properties
  • Logistic Regression has no hyperparameters beyond C (regularization strength). Very few knobs to turn.
  • Coefficients are interpretable: exp(w_i) is the odds ratio for feature i. Positive w_i → feature pushes toward class 1.
  • Fast to train: Especially with solver='liblinear' for binary. Scales to millions of samples.
  • Probabilistic: Outputs are true probabilities (calibrated). Use .predict_proba(X).

Handling Class Imbalance

When one class is much rarer than the other, logistic regression biases toward the common class:

Solutions
  • class_weight='balanced': Automatically reweights loss for each class inversely proportional to its frequency. Default recommendation.
  • Adjust threshold: Default threshold is 0.5. If positive class is rarer, lower threshold to 0.3 or 0.2 to get more predictions of the rare class.
  • Use appropriate metric: Don't optimize accuracy. Use F1, PR-AUC, or recall depending on your problem.
Common Gotchas
  • C parameter is inverse λ. Large C = less regularization, small C = more regularization. Counterintuitive but standard sklearn convention.
  • Feature scaling matters. Not as critical as SVMs, but scaled features lead to more stable coefficient estimates.
  • Assumes linear separability. If your decision boundary is obviously non-linear, polynomial features or a different model (trees, SVM) will help.
  • Probability outputs are only reliable if you have sufficient training data. With very few samples, predicted probabilities are overconfident.

Decision Trees

Recursive binary splits that partition the feature space. Simple, interpretable, and prone to overfitting.

The Algorithm

Recursively partition data by asking binary questions ("Is feature_3 > 7.5?"). At each node, pick the split that best reduces impurity (Gini for classification, MSE for regression).

Scikit-Learn Implementation
  • from sklearn.tree import DecisionTreeClassifier, DecisionTreeRegressor
  • Key parameters:
  • max_depth: Maximum tree depth. Lower = simpler, less overfit. Start with 3–7.
  • min_samples_split: Minimum samples in a node to split. Default 2. Increase to reduce overfitting.
  • min_samples_leaf: Minimum samples in a leaf. Default 1. Increase to reduce overfitting.
  • criterion: 'gini' or 'entropy' for classification. Usually 'gini' is faster.
  • Usage: DecisionTreeClassifier(max_depth=5, min_samples_split=10).fit(X_train, y_train)

Feature Importance

Built-in feature importance ranks features by how much they reduce impurity across all nodes. Not causal, but useful for feature selection and exploration.

Important Notes on Feature Importance
  • Importance is relative — only inter-feature comparisons are meaningful.
  • Correlated features split importance — if two features are highly correlated, only one will be used at the top splits, and the other will have low importance.
  • High importance does NOT mean "predictive after controlling for other features." It means "was chosen early in the tree."
  • For a more robust importance measure, use permutation importance from sklearn.inspection.

The Overfitting Problem

Trees Are Greedy and Prone to Overfitting
  • A fully grown tree memorizes training data — each leaf may have a single sample. Perfect train accuracy, terrible test accuracy.
  • Why: Trees have no built-in regularization term. Greedy algorithm makes locally optimal splits, not globally optimal structure.
  • Fixes:
  • Limit max_depth — simple control, often sufficient.
  • Increase min_samples_split and min_samples_leaf — require nodes to have enough data.
  • Use ensemble methods (Random Forest, Gradient Boosting) — combine many trees to reduce variance.

When to Use Decision Trees

Pros and Cons
  • Pros: Interpretable (explain decision path), no scaling needed, handles mixed data types, non-linear boundaries.
  • Cons: High variance (small data changes → different tree), greedy algorithm, often beaten by ensembles or linear models.
  • Best for: Interpretability and explaining decisions to stakeholders. For raw predictive power, ensemble methods are superior.

Random Forests

The workhorse of tabular ML: trains many trees in parallel, each on a bootstrap sample with random feature subsets. Reduces variance dramatically.

How It Works

1
Train N trees (e.g., 100). Each tree is trained on a bootstrap sample — random sample with replacement from training data.
2
At each split, consider only a random subset of features (sqrt(n_features) for classification, typically). Forces trees to be different.
3
Predictions: For classification, majority vote across all trees. For regression, average.
Key Insight: Bagging + Feature Subsampling
  • Bagging (Bootstrap Aggregating): Train on random subsets, combine predictions. Reduces variance by averaging uncorrelated predictions.
  • Feature Subsampling: If you don't subselect features, all trees would pick the same dominant features → highly correlated → averaging doesn't help.
  • Random Forests decorrelate trees → averaging becomes powerful.
  • Out-of-bag (OOB) error: Each tree sees ~63% of data. Use the remaining 37% as a free validation set. sklearn's oob_score_ computes this automatically.
Scikit-Learn Implementation
  • from sklearn.ensemble import RandomForestClassifier, RandomForestRegressor
  • Key parameters:
  • n_estimators: Number of trees. More = better (diminishing returns), but slower. Default 100. Try 50–500.
  • max_depth: Usually leave unset (grows full). Random Forests don't need to be shallow — bagging handles overfitting.
  • min_samples_split/leaf: Usually default (2/1). Tighten to limit individual tree size.
  • max_features: Number of features to consider per split. Default 'sqrt' for classification, 'log2' for regression.
  • n_jobs: -1 to use all cores. Training is embarrassingly parallel.
  • Usage: RandomForestClassifier(n_estimators=100, n_jobs=-1).fit(X_train, y_train)

Feature Importance

Random Forests' feature importance is more robust than single trees because it averages over 100 trees. Still not causal, but directionally useful.

When Random Forests Struggle
  • With very high-dimensional data: If n_features >> n_samples, Random Forests may still overfit despite bagging. Consider feature selection or dimensionality reduction first.
  • With imbalanced classes: Random Forests don't automatically handle this. Use class_weight='balanced' or resample.
  • Training time: With many trees and large data, training can be slow. Use n_jobs=-1 and consider Gradient Boosting (faster empirically) if speed matters.

Naive Bayes

Probabilistic classifier based on Bayes' theorem. Assumes features are conditionally independent — "naive" but often works well in practice.

The Idea

Bayes' theorem: P(y|x) ∝ P(x|y) · P(y). The classifier finds the class y that maximizes this posterior probability. The "naive" assumption: all features are independent given the class. This simplification makes computation tractable.

P(y|x₁, x₂, ..., xₙ) ∝ P(y) · ∏ᵢ P(xᵢ|y)
// Predict: argmax_y [log(P(y)) + Σᵢ log(P(xᵢ|y))]

Three Flavors

VariantDistributionBest For
Gaussian NBContinuous features ~ NormalGeneral-purpose; assume features normally dist.
Multinomial NBCount data (frequencies)Text classification; word counts in documents
Bernoulli NBBinary featuresBinary text data; presence/absence of words
Scikit-Learn Implementation
  • from sklearn.naive_bayes import GaussianNB, MultinomialNB, BernoulliNB
  • Gaussian (continuous data): GaussianNB().fit(X_train, y_train)
  • Multinomial (text/counts): MultinomialNB().fit(X_train, y_train) — often paired with TfidfVectorizer.
  • Bernoulli (binary features): BernoulliNB().fit(X_train, y_train)
  • Key parameter: alpha (Laplace smoothing, prevents zero probabilities). Default 1.0; increase if you have sparse data.

Why Naive Bayes Works Despite Naivety

The Paradox
  • The independence assumption is almost always violated — features in real data are correlated.
  • Yet Naive Bayes often works well in practice, especially for text and high-dimensional data.
  • Why: For classification, you only need to rank classes correctly (argmax), not estimate probabilities accurately. Wrong assumptions don't break ranking if they're wrong in a symmetric way.
  • High-dimensional data: curse of dimensionality makes density estimation hard for other methods; Naive Bayes sidesteps this with the independence assumption.

Strengths and Limitations

When to Use / Avoid
  • Strengths: Fast, trains in one pass, works well with high-dimensional text, easy to implement, no tuning (besides alpha).
  • Weaknesses: Independence assumption limits expressiveness. Usually beaten by logistic regression or tree-based models on structured data.
  • Best for: Text classification (spam filters, sentiment), baseline comparisons, when you need real probability estimates (not just scores).

k-Nearest Neighbors

The simplest algorithm: classify by majority vote of k nearest training points. No training, just lookup.

The Algorithm

Given a test point, find its k nearest neighbors in the training set (by Euclidean distance, by default). For classification, predict the majority class. For regression, predict the mean value.

ŷ = argmax_c [count of neighbors of class c]   // classification
ŷ = mean(y_values of k neighbors)                   // regression
Scikit-Learn Implementation
  • from sklearn.neighbors import KNeighborsClassifier, KNeighborsRegressor
  • Key parameters:
  • n_neighbors: Number of neighbors to consider. Default 5. Must tune — too low = noisy, too high = biased.
  • metric: Distance metric ('euclidean', 'manhattan', 'cosine', etc.). Default 'euclidean'. Use 'cosine' for high-dim text/sparse data.
  • weights: 'uniform' (all neighbors equal) or 'distance' (closer neighbors weighted higher). Default 'uniform'.
  • n_jobs: -1 for parallelization. Prediction becomes fast when parallelized.
  • Usage: KNeighborsClassifier(n_neighbors=5, metric='euclidean').fit(X_train, y_train)

Choosing k

The Bias-Variance Tradeoff in k
  • Small k (e.g., 1, 3): High variance (sensitive to individual noisy points), low bias. Can overfit.
  • Large k (e.g., n-1): Low variance, high bias. Eventually predicts the global majority class — useless.
  • Rule of thumb: Start with k = sqrt(n) where n is number of samples. Tune via cross-validation. Odd k avoids ties in binary classification.

The Curse of Dimensionality

KNN Fails in High Dimensions
  • As dimensions increase, Euclidean distances become meaningless — all points are roughly equidistant from each other.
  • KNN's "nearest" neighbors aren't actually that similar. The algorithm breaks down.
  • Fixes:
  • Dimensionality reduction (PCA) before KNN.
  • Feature selection to remove irrelevant features.
  • Use distance metric aware of sparsity (cosine for text/sparse data).

Strengths and Limitations

Pros and Cons
  • Pros: Simple, non-parametric (adapts to data shape), no training phase, works with any distance metric.
  • Cons: Slow prediction (compute distance to all training points), high memory (stores all training data), fails in high dimensions without preprocessing.
  • Best for: Small-to-medium datasets, low/medium dimensions, baseline comparisons, time-sensitive training (no training time is needed).

Support Vector Machines

Find the decision boundary with maximum margin. Powerful non-linear boundaries via the kernel trick. Theoretically elegant.

The Core Geometry

SVM finds a hyperplane that separates two classes with maximum margin — the gap between the closest points of each class and the boundary. Intuition: a wide margin likely generalizes better.

Key Concepts
  • Support vectors: The training points closest to the decision boundary (the "toughest" points). Only these matter — the rest are irrelevant. This sparsity is what makes SVMs memory-efficient.
  • Hard margin: Assumes data is linearly separable. Rarely true in practice.
  • Soft margin: Allows some points to violate the margin, controlled by regularization hyperparameter C.
Scikit-Learn Implementation
  • from sklearn.svm import SVC, SVR (for classification and regression)
  • Key parameters:
  • C: Regularization strength. Large C = smaller margin allowed, risk overfitting. Small C = larger margin, risk underfitting.
  • kernel: 'linear' (for linearly separable data), 'rbf' (default, non-linear), 'poly' (polynomial degree d), 'sigmoid'. RBF is the go-to.
  • gamma (RBF only): Controls influence of single training sample. High gamma = each point influences far; low gamma = local influence. Default 'scale' (1/(n_features * X.var())).
  • probability: If True, outputs probabilities via Platt scaling (slow, inaccurate). Default False.
  • Usage: SVC(C=1.0, kernel='rbf', gamma='scale').fit(X_train, y_train)

The Kernel Trick

SVM can implicitly map data into a higher-dimensional space where it becomes linearly separable — without explicitly computing the mapping. This is done via kernel functions K(x, x') that compute dot products in the high-dim space efficiently.

KernelFormulaWhen to use
Linearxᵀx'Linearly separable; high-dim text data
RBF (Gaussian)exp(−γ‖x−x'‖²)Non-linear boundary; default safe choice
Polynomial(xᵀx' + r)^dWhen you suspect degree-d interactions

SVMs in Practice: Strengths & Limitations

Critical Considerations
  • Feature scaling is essential. SVM uses distance metrics sensitive to scale. Always standardize before fitting.
  • Tuning C and gamma is crucial. Use GridSearchCV over logarithmic ranges: C in [0.01, 0.1, 1, 10, 100], gamma in [0.001, 0.01, 0.1, 1].
  • Doesn't scale to large n. Training complexity is O(n²) to O(n³). Avoid for n > ~100,000. Use SGDClassifier instead.
  • Probability outputs unreliable. The probability=True option uses Platt scaling, which is slow and inaccurate. If you need probabilities, use Logistic Regression.
  • Works well in high-dimensional spaces. Unlike KNN, SVMs don't suffer from curse of dimensionality. Great for text, genomics.

SVC vs SVR

SVC is for classification; SVR is for regression. Both use the same kernel trick and margin concepts. SVR minimizes ε-insensitive loss instead of classification error — allows tube of predictions rather than perfect predictions.
