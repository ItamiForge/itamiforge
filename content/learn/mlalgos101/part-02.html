Gradient Boosting (sklearn)

Build trees sequentially, each correcting errors of the previous. The foundation for XGBoost and LightGBM.

How It Works

Gradient Boosting trains trees sequentially. Each new tree is fit to the residuals (errors) of all previous trees. The final prediction is the sum of all trees.

F(x) = f₁(x) + learning_rate · f₂(x) + learning_rate · f₃(x) + ...
// Each tree f_t predicts the negative gradient of the loss w.r.t. previous predictions
Key Insight
  • Unlike Random Forests (parallel), boosting is sequential — each tree "sees" and corrects mistakes of previous trees.
  • This sequential refinement typically leads to lower bias than RF. But boosting can overfit if not regularized.
  • learning_rate (shrinkage) is critical — it scales each tree's contribution, preventing overfitting.
Scikit-Learn Implementation
  • from sklearn.ensemble import GradientBoostingClassifier, GradientBoostingRegressor
  • Key parameters:
  • n_estimators: Number of boosting stages. More → lower bias, risk overfit. Typical: 50–500.
  • learning_rate: Shrinkage (0–1). Lower = more conservative, requires more trees, but often better generalization. Typical: 0.01–0.1.
  • max_depth: Tree depth. Usually shallow (3–7). Deeper trees = more complex interactions captured, but slower and more prone to overfit.
  • min_samples_split/leaf: Minimum samples to split/in leaf. Increase to regularize.
  • subsample: Row subsampling ratio (0–1). Like bagging effect. 0.8–1.0 typical.
  • validation_fraction: Fraction held for early stopping. When val error stops decreasing, stop training.

Hyperparameter Tuning Strategy

1
Start with low learning_rate (0.01–0.05) and high n_estimators (200–500). Use early stopping.
2
Tune max_depth (3–8) and min_samples_split/leaf via GridSearchCV.
3
If still overfitting, increase subsample or decrease learning_rate.
4
Use early stopping to avoid tuning n_estimators manually.
Common Pitfalls
  • High learning_rate + high n_estimators = overfitting. Low learning rate requires more trees — this is by design.
  • Deep trees in boosting overfit. Unlike Random Forests, keep boosted trees shallow (depth 2–7).
  • Imbalanced classes: Use scale_pos_weight or subsample minority class.

XGBoost

The dominant machine learning model for structured data. Speed, regularization, and flexibility.

What Makes XGBoost Better?

XGBoost (eXtreme Gradient Boosting) is an optimized implementation of gradient boosting with:

Key Advances
  • Speed: C++ backend, GPU support, parallelization. 10–100x faster than sklearn's GradientBoosting.
  • Regularization: Built-in L1/L2 penalties on tree weights. Reduces overfitting without external tricks.
  • Handling missing values: Learns the optimal direction for missing data per feature.
  • Custom loss functions: Implement any differentiable loss.
  • Built-in cross-validation and early stopping.
Installation & Implementation
  • Install: pip install xgboost
  • from xgboost import XGBClassifier, XGBRegressor
  • Core parameters (familiar from sklearn):
  • n_estimators, max_depth, learning_rate, subsample
  • XGBoost-specific:
  • gamma: Minimum loss reduction to split. Higher = more conservative (less overfitting).
  • lambda, alpha: L2 and L1 regularization. Default 1.0 and 0. Increase to reduce overfitting.
  • early_stopping_rounds: Stop if val metric doesn't improve for N rounds.
  • Usage: XGBClassifier(n_estimators=100, max_depth=5, learning_rate=0.1).fit(X_train, y_train, eval_set=[(X_val, y_val)], early_stopping_rounds=10)

Training with Validation Set

Early Stopping Pattern
  • eval_set: Pass a list of (X, y) tuples. XGBoost monitors the primary metric on these.
  • eval_metric: Which metric to monitor ('logloss' for binary, 'mlogloss' for multiclass, 'rmse' for regression).
  • early_stopping_rounds: If metric doesn't improve for N consecutive rounds, stop training. Avoids overfitting automatically.
  • Example: Stop if validation AUC doesn't improve for 20 rounds.
XGBoost Gotchas
  • Features must be numeric: Encode categorical variables or use max_cat_to_onehot parameter.
  • Hyperparameter tuning is important. Default params are often too high (risk overfit). Start conservative.
  • Tree-based models don't need feature scaling, but they do need clean data (no NaNs passed post-training).
  • Watch out for data leakage: If val_set overlaps with train_set, early stopping is meaningless.

LightGBM

Microsoft's answer to XGBoost. Faster on large datasets, handles categorical variables natively, competitive accuracy.

Why LightGBM?

LightGBM (Light Gradient Boosting Machine) is a faster alternative to XGBoost, especially on large datasets. Key differences:

LightGBM vs XGBoost
  • Leaf-wise tree growth (vs level-wise): LightGBM grows the leaf with max loss reduction. This can lead to deeper, more accurate trees faster.
  • Categorical support: LightGBM handles categorical features natively — no need to encode. Faster and often more accurate.
  • Speed: 10–20x faster on large data (1M+ rows) because of binning and leaf-wise growth.
  • Memory efficiency: Uses histogram-based learning. More RAM-efficient.
  • Trade-off: May overfit on small datasets. Needs more regularization tuning.
Installation & Implementation
  • Install: pip install lightgbm
  • from lightgbm import LGBMClassifier, LGBMRegressor
  • Key parameters:
  • num_leaves: Max leaves per tree (replaces max_depth; more direct control over tree complexity).
  • learning_rate, n_estimators, subsample: Same as XGBoost.
  • min_data_in_leaf: Minimum samples in a leaf. Increase to reduce overfitting.
  • feature_fraction: Fraction of features to consider per tree. Default 1.0.
  • categorical_feature: List of categorical feature indices. LightGBM will split on them without encoding.
  • Usage: LGBMClassifier(num_leaves=31, learning_rate=0.05, n_estimators=100).fit(X_train, y_train, categorical_feature=[...])

When to Use LightGBM

Decision Guide
  • Use LightGBM if: (1) Dataset > 100K rows, (2) Many categorical features, (3) Speed matters, (4) Memory is limited.
  • Use XGBoost if: (1) Dataset < 100K rows, (2) Already have XGBoost pipeline, (3) Need stability (XGBoost is slightly more robust).
  • In practice: Start with LightGBM if you have large data. Try both if unsure.
LightGBM Gotchas
  • Overfits on small data. If n < 10K, use XGBoost or increase min_data_in_leaf, decrease num_leaves.
  • Categorical encoding: Pass categorical features by index, not one-hot encoded. More efficient.
  • Monotonicity constraints: LightGBM can enforce monotone_constraints (feature always increases/decreases prediction). Useful for fairness/interpretability.

CatBoost

Yandex's gradient boosting. Excels with categorical data and is remarkably robust to overfitting out of the box.

What's Special About CatBoost?

CatBoost (Categorical Boosting) is optimized for datasets with many categorical features. It handles them differently than XGBoost/LightGBM:

CatBoost Advantages
  • Categorical handling: Automatically handles categorical features without explicit encoding. Can use target encoding intelligently.
  • Robust by default: Less overfitting with default parameters compared to XGBoost/LightGBM. "Works out of the box."
  • Target encoding: Uses permutation-based target encoding to avoid target leakage in cross-validation.
  • GPU support: Multiple GPU training for very large datasets.
  • Trade-off: Slower training than LightGBM on large datasets (not as optimized for speed).
Installation & Implementation
  • Install: pip install catboost
  • from catboost import CatBoostClassifier, CatBoostRegressor
  • Key parameters:
  • iterations: Number of boosting rounds (equivalent to n_estimators). Default 100.
  • depth: Tree depth. Default 6. CatBoost tends to use deeper trees than XGBoost.
  • learning_rate: Default 0.03. Lower for more stability.
  • cat_features: List of indices/names of categorical features. Must be specified.
  • early_stopping_rounds: Same as XGBoost.
  • Usage: CatBoostClassifier(iterations=100, depth=6, cat_features=['feature_1', 'feature_2']).fit(X_train, y_train, eval_set=(X_val, y_val))

When to Use CatBoost

Decision
  • Use CatBoost if: (1) Many categorical features, (2) Want less tuning (robust defaults), (3) Trust that target encoding won't cause leakage (uses permutation-based approach).
  • Avoid if: (1) Dataset > 1M rows and speed is critical (LightGBM is faster), (2) Need explainability (CatBoost's target encoding is less interpretable).

ARIMA & Classical Time Series

AutoRegressive Integrated Moving Average. The workhorse of classical forecasting for decades.

The ARIMA Model

ARIMA(p, d, q) has three components:

ARIMA Components
  • AR (AutoRegressive, p): Regress on past values. y_t = c + φ₁·y_{t-1} + φ₂·y_{t-2} + ... + ε_t
  • I (Integrated, d): Differencing to make series stationary. d=0 (stationary already), d=1 (first difference), d=2 (second difference).
  • MA (Moving Average, q): Regress on past forecast errors. y_t = ε_t + θ₁·ε_{t-1} + θ₂·ε_{t-2} + ...
Implementation (statsmodels)
  • Install: pip install statsmodels
  • from statsmodels.tsa.arima.model import ARIMA
  • model = ARIMA(y_train, order=(p, d, q)).fit()
  • forecast = model.get_forecast(steps=10).conf_int() — returns mean + confidence intervals.
  • Key parameter: order — tuple (p, d, q).

Choosing p, d, q — The Hard Part

1
Check stationarity: Plot ACF/PACF, run ADF test. If non-stationary, difference (increase d) until stationary.
2
ACF/PACF plots: PACF tells you p (AR order); ACF tells you q (MA order). Look for cutoff in plots.
3
Grid search: Try p, q in [0, 5], d in [0, 2]. Fit each. Pick via AIC/BIC.
ARIMA Limitations
  • Assumes linear dynamics. Non-linear patterns (seasonality, regime changes) need extensions (SARIMA, VAR).
  • Requires stationarity. Non-stationary series need differencing. Differencing loses information.
  • Short-horizon forecasting: Good for 1–12 steps ahead. Beyond that, predictions revert to the mean.
  • Seasonal data: Use SARIMA (Seasonal ARIMA). Add seasonal parameters (P, D, Q, s).

Prophet & Modern Time Series

Facebook's Prophet: handles seasonality, trend changes, and holidays elegantly. Nixtla's StatsForecast for speed.

Prophet — User-Friendly Forecasting

Prophet decomposes a time series into trend, seasonality, and holiday components. Robust to missing data and outliers.

Implementation
  • Install: pip install pystan prophet (or cmdstanpy backend)
  • from prophet import Prophet
  • Data format: DataFrame with columns 'ds' (date) and 'y' (value).
  • model = Prophet(yearly_seasonality=True, weekly_seasonality=True)
  • model.fit(df)
  • future = model.make_future_dataframe(periods=30) — 30 periods forward.
  • forecast = model.predict(future) — returns 'yhat' (prediction), 'yhat_lower', 'yhat_upper'.
Prophet Advantages
  • Handles seasonality automatically. Detects yearly, weekly, daily patterns.
  • Trend changepoints: Automatically detects when trends shift.
  • Holiday effects: holidays parameter can specify known holidays' impact.
  • Robust: Built-in handling of missing data, outliers.
  • Interpretable: Decomposes into components. Easy to understand drivers.
  • Easy to use: Few hyperparameters to tune. Works out-of-box.

Modern Alternative: StatsForecast (Nixtla)

For faster, ensemble forecasting with automatic model selection:

StatsForecast
  • Install: pip install statsforecast
  • Multiple algorithms: ARIMA, ExponentialSmoothing, AutoRegressive, etc.
  • Ensemble forecasting: combines multiple models automatically.
  • Fast (vectorized, ML-optimized).
  • Ideal for many time series (10s to 1000s). Prophet better for single series.
When to Use
  • Prophet: Single to few time series, need interpretability, have holidays/events to account for.
  • ARIMA: Stationary series, need statistical rigor, small amount of data.
  • StatsForecast/Nixtla: Many time series, want ensemble, speed matters.
  • Deep Learning (Transformer-based): Very long series, complex multivariate patterns. Part 3.

Anomaly Detection

Finding outliers and unusual patterns. Isolation Forest and Local Outlier Factor are the standards.

Why Anomaly Detection is Hard

"Anomaly" is context-dependent. A value that's anomalous in one distribution might be normal in another. Most algorithms look for points that are statistically unlikely or far from the bulk of data.

Isolation Forest

Isolation Forest isolates anomalies recursively by randomly selecting features and split values. Anomalies isolate faster (fewer splits needed) than normal points.

Scikit-Learn Implementation
  • from sklearn.ensemble import IsolationForest
  • clf = IsolationForest(contamination=0.05).fit(X_train) — assumes 5% anomalies.
  • predictions = clf.predict(X_test) — returns 1 (normal) or -1 (anomaly).
  • scores = clf.score_samples(X_test) — returns anomaly scores (lower = more anomalous).
  • Key parameter: contamination — expected fraction of outliers (0–0.5). If unknown, estimate via domain knowledge or statistical methods.
Isolation Forest Advantages
  • No distance computation: Uses tree-based isolation, works in high dimensions.
  • Fast: O(n log n) time and O(n log n) space.
  • Works on raw features: No scaling needed.
  • Handles high-dimensional data gracefully. Unlike k-NN.

Local Outlier Factor (LOF)

LOF compares the local density of each point to its neighbors' densities. Points with much lower density than neighbors are anomalies (e.g., points in a sparse region surrounded by dense clusters).

Implementation
  • from sklearn.neighbors import LocalOutlierFactor
  • lof = LocalOutlierFactor(n_neighbors=20, contamination=0.05).fit(X_train)
  • predictions = lof.negative_outlier_factor_ — use this for scoring.
  • Key parameter: n_neighbors — affects sensitivity. More neighbors = coarser detection.
