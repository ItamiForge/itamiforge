Module 01 / Foundations

The ML Landscape

What machine learning actually is, and how its three paradigms are fundamentally different.

What is Machine Learning?

Traditional programming is rules → data → output. You encode logic explicitly. Machine learning flips this: you give it data + desired outputs → it infers the rules. The "rules" are parameters of a mathematical model, and "learning" is optimizing those parameters to minimize error.

Arthur Samuel's classic definition: "Field of study that gives computers the ability to learn without being explicitly programmed." More precisely — a program learns from experience E with respect to task T and performance P, if its P on T improves with E.

Core Vocabulary
  • Features (X): Input variables — the raw data your model sees.
  • Labels / Targets (y): What you're trying to predict (in supervised learning).
  • Model: A mathematical function f(X; θ) parameterized by θ that maps X → ŷ.
  • Training: Adjusting θ to minimize the gap between ŷ and y on a training set.
  • Inference: Running the trained model on new, unseen data.
  • Generalization: How well the model performs on data it hasn't seen — the real goal.

Three Paradigms

🎯

Supervised Learning

Learn a mapping X→y from labeled examples. Error signal is explicit — you know the right answer.

🔍

Unsupervised Learning

Find structure in unlabeled data. No ground truth — the model discovers patterns, clusters, or representations.

🎮

Reinforcement Learning

An agent takes actions in an environment to maximize cumulative reward. No labeled data — learns by trial and error.

The Data Split — Always

Why you need three splits
  • Training set (~70%): Model sees and learns from this. Parameters are optimized here.
  • Validation set (~15%): Hyperparameter tuning and model selection. Model never trains on this, but you peek at it to make decisions — so it's "contaminated" for final evaluation.
  • Test set (~15%): Touched exactly ONCE at the very end. This is your unbiased estimate of real-world performance.
Key Gotchas
  • Data leakage: If test-set information bleeds into training (e.g., scaling using the full dataset's mean), your evaluation is optimistically biased. Fit scalers/preprocessors on train, apply to val/test.
  • i.i.d. assumption: Most ML theory assumes data is independently and identically distributed. Time-series, geo-clustered, or grouped data violates this — use temporal/grouped splits instead of random splits.
  • More data beats better algorithms more often than you'd think. Before tuning models, verify your data pipeline is clean.

The ML Workflow

1
Problem framing: Is it regression, classification, clustering? Define the loss you actually care about, not just what's easy to optimize.
2
Data collection & EDA: Understand distributions, check for nulls, outliers, class imbalance. Garbage in = garbage out.
3
Feature engineering: Transform raw data into a form the model can use. Often the highest-leverage activity in classical ML.
4
Model selection & training: Start simple (linear models, trees). Complexity only if needed.
5
Evaluation: On held-out data. Use the right metric for your problem, not just accuracy.
6
Iteration: Diagnose errors, improve data or model, repeat. Most time is spent here.

Gradient Descent

The engine behind almost everything. Understanding this is understanding how models learn.

The Core Idea

You have a loss function L(θ) that measures how wrong your model is. Learning = finding θ that minimizes L. Gradient descent does this by iteratively moving θ in the direction of steepest decrease — opposite to the gradient.

θ ← θ − α · ∇θL(θ)
// α = learning rate, ∇L = gradient (direction of steepest ascent)

Think of it as a ball rolling down a hilly landscape. The gradient tells you the slope at your current position. You take a small step downhill, recompute the slope, repeat.

Why the Negative Gradient?
  • The gradient ∇L points in the direction of steepest increase of L.
  • We want to decrease L, so we move in the opposite direction: −∇L.
  • The learning rate α scales how large each step is.

Three Variants — Critical Distinction

VariantComputes gradient overProsCons
Batch GDEntire datasetStable, guaranteed convergence (convex)Slow for large data; can't fit in memory
Stochastic GD (SGD)1 sample at a timeFast updates, escapes local minimaNoisy, oscillates around minimum
Mini-batch GDBatch of N samples (e.g. 32–256)Best of both — parallelizable on GPUBatch size is a new hyperparameter

In practice, mini-batch GD is the default for almost everything. When people say "SGD" in deep learning, they usually mean mini-batch.

Learning Rate — The Most Important Hyperparameter

Too Large (α ↑↑)

Overshoots the minimum, loss oscillates or diverges. Model fails to converge.

Too Small (α ↓↓)

Extremely slow convergence. May get stuck in shallow local minima or saddle points.

Implementation Pointers
  • Start with a learning rate finder: sweep LR from very small to large, plot loss vs LR, pick the LR just before loss starts rising.
  • Use learning rate schedules: step decay, cosine annealing, or warmup + decay (standard in deep learning).
  • Feature scale your inputs first — unscaled features create an elongated loss landscape where GD zigzags inefficiently.

Modern Optimizers (beyond vanilla GD)

Key Optimizers
  • Momentum: Accumulates velocity in the gradient direction. Dampens oscillations. v ← βv + (1-β)∇L; θ ← θ − αv
  • RMSProp: Adapts learning rate per-parameter by dividing by a running average of squared gradients. Good for RNNs.
  • Adam (Adaptive Moment Estimation): Combines momentum + RMSProp. The practical default for most deep learning. Maintains first moment (mean) and second moment (variance) of gradients.
Adam:
m ← β₁m + (1−β₁)∇L   // 1st moment (momentum)
v ← β₂v + (1−β₂)(∇L)²  // 2nd moment (adaptive scale)
θ ← θ − α · m̂ / (√v̂ + ε) // bias-corrected update
Gotchas
  • Local minima: In high-dimensional spaces (deep nets), local minima are rare. Saddle points are the bigger problem — GD can stall there. Momentum helps escape.
  • Vanishing/exploding gradients: In deep networks, gradients can shrink to zero (vanish) or blow up (explode) during backpropagation through many layers. Use gradient clipping, batch norm, residual connections.
  • Adam can generalize worse than SGD sometimes in vision tasks. SGD + momentum with careful tuning often beats Adam on CNNs.

Bias–Variance Tradeoff

The central tension in all of machine learning — and why you can't just make your model "more powerful".

Decomposing Generalization Error

For any model, the expected test error decomposes into three terms:

Error = Bias² + Variance + Irreducible Noise
// Irreducible noise = inherent randomness in data, can't be reduced

Bias

Error from wrong assumptions in the model. A linear model fitting a quadratic relationship has high bias — it systematically gets things wrong. Also called underfitting.

Variance

Error from sensitivity to fluctuations in training data. A 20-degree polynomial memorizes training noise — its predictions change wildly on new data. Also called overfitting.

Intuition via a Target Analogy
  • Low bias, low variance: All shots clustered at the bullseye. Ideal. Hard to achieve.
  • High bias, low variance: Shots clustered consistently, but far from center. Confidently wrong.
  • Low bias, high variance: Shots scatter around the bullseye but no single shot is close. Unreliable.
  • High bias, high variance: Scattered AND far from center. The worst case. Usually means a broken training loop.

Diagnosing Underfitting vs Overfitting

SymptomTrain ErrorVal ErrorDiagnosis
Both highHighHighUnderfitting — model too simple or too little training
Gap between themLowHighOverfitting — model memorized training data
Both lowLowLowWell-fit — generalization is working

Regularization — Fighting Overfitting

Regularization adds a penalty to the loss function that discourages large parameter values, effectively constraining model complexity.

L2 (Ridge):   L_total = L_data + λ · Σwᵢ²
L1 (Lasso):   L_total = L_data + λ · Σ|wᵢ|
// λ = regularization strength. Larger λ = more regularization
L1 vs L2 — Critical Difference
  • L2 (Ridge): Shrinks all weights smoothly toward zero. Never exactly zero. Handles correlated features well. Closed-form solution exists.
  • L1 (Lasso): Produces sparse weights — many become exactly zero. Acts as automatic feature selection. Useful when you believe most features are irrelevant.
  • Elastic Net: Combines both: λ₁|w| + λ₂w². Good default when you don't know which to pick.

Other Regularization Techniques

Implementation Pointers
  • Dropout (neural nets): During training, randomly zero out neurons with probability p. Forces the network to learn redundant representations. Disable at inference time.
  • Early stopping: Track validation loss during training. Stop when validation loss starts increasing (before you overfit). Save the checkpoint at validation minimum.
  • Data augmentation: Artificially expand training set (flips, crops, color jitter for images). Effectively increases dataset size without collecting new data.
  • Batch normalization: Normalizes activations within each mini-batch. Stabilizes training, allows higher learning rates, mild regularization effect.
  • Cross-validation (k-fold): Rotate through k splits for training/validation. More reliable estimate of generalization than a single split, especially for small datasets.
Common Mistakes
  • Adding more parameters when val loss is already higher than train loss. That's overfitting — you need regularization or more data, not complexity.
  • Tuning on the test set. If you check test performance 20 times, your final number is statistically meaningless.
  • Regularization hyperparameter λ should be swept on a log scale (0.0001, 0.001, 0.01, 0.1, 1) not linear scale.

Linear Regression

The simplest model that can teach you everything: parameterization, loss, optimization, and evaluation.

The Model

Assumes a linear relationship between inputs X and a continuous output y.

ŷ = Xw + b   // or equivalently: ŷ = wᵀx + b for a single sample
// w = weight vector (one per feature), b = bias/intercept

The model has n+1 parameters for n features (n weights + 1 bias). Learning = finding w and b that minimize prediction error.

Loss Function: Mean Squared Error

MSE = (1/m) · Σᵢ (yᵢ − ŷᵢ)²
// m = number of training samples. Squaring penalizes large errors more.

Why squared and not absolute? MSE is differentiable everywhere — critical for gradient-based optimization. The gradient of MSE w.r.t. w is clean: ∇w = (2/m) · Xᵀ(Xw − y)

Two Ways to Optimize

Normal Equation (closed-form)

Solve analytically: w* = (XᵀX)⁻¹ Xᵀy

Exact solution. O(n³) matrix inversion — infeasible for n > ~10,000 features. Good for small/medium datasets.

Gradient Descent

Iteratively update w in the direction of −∇MSE. Scales to millions of features. Requires feature scaling and tuning α.

Geometric Interpretation
  • Each weight wᵢ is the marginal effect of feature xᵢ on ŷ, holding all else constant.
  • The model fits a hyperplane through the feature space to minimize vertical distance to data points.
  • MSE minimization = projecting y onto the column space of X.

Evaluation Metrics

MetricFormulaWhen to use
MSEmean((y−ŷ)²)Optimization target; penalizes large errors heavily
RMSE√MSESame units as y; easier to interpret
MAEmean(|y−ŷ|)More robust to outliers than MSE
R²1 − SS_res/SS_totProportion of variance explained. 1 = perfect.
Implementation Pointers
  • Always standardize features before gradient descent (subtract mean, divide by std). Otherwise, features on different scales create an elongated loss landscape and GD converges slowly.
  • Check for multicollinearity (features correlated with each other). It inflates variance of weight estimates, makes coefficients unstable. Use Ridge regression or PCA to handle it.
  • Plot residuals vs fitted values. Patterns in residuals reveal violations of linearity assumption or heteroscedasticity.
  • Polynomial features (x, x², x³) extend linear regression to capture non-linear relationships while keeping the same linear framework.
Assumptions of OLS (Ordinary Least Squares)
  • Linearity: y is a linear function of X.
  • Independence: Observations are independent (no autocorrelation).
  • Homoscedasticity: Residuals have constant variance across all values of X.
  • Normality of residuals: For inference (p-values, confidence intervals) to be valid.
  • Violating these doesn't break prediction, but it breaks statistical inference (coefficient interpretation, p-values).

Logistic Regression

Despite the name, it's a classification algorithm. Arguably the most important model to truly understand.

The Problem with Linear Regression for Classification

For binary classification (y ∈ {0, 1}), applying linear regression gives predictions outside [0, 1]. These are meaningless as probabilities. We need a model that outputs a value bounded in (0, 1) — interpreted as P(y=1 | x).

The Sigmoid Function

σ(z) = 1 / (1 + e⁻ᶻ)   // "squashes" any real number into (0, 1)
z = wᵀx + b   // the "logit" — a linear function of inputs
ŷ = σ(wᵀx + b) = P(y=1 | x)
Key Properties of Sigmoid
  • σ(0) = 0.5 — at the decision boundary, the model is exactly uncertain.
  • σ(z) → 1 as z → +∞; σ(z) → 0 as z → −∞
  • Derivative: σ'(z) = σ(z)(1 − σ(z)) — elegant, used in backprop.
  • The decision boundary (where ŷ = 0.5) is where wᵀx + b = 0 — a linear boundary in feature space. Logistic regression is a linear classifier.

Loss: Binary Cross-Entropy

MSE is the wrong loss for classification (non-convex with sigmoid, saturates gradients). Binary cross-entropy (log loss) is derived from maximum likelihood estimation:

L = −(1/m) · Σ [ yᵢ log(ŷᵢ) + (1−yᵢ) log(1−ŷᵢ) ]
// When y=1: only the first term matters. When y=0: only the second term.
// Penalizes confident wrong predictions very heavily (log(0) → ∞)
Intuition for Cross-Entropy
  • If y=1 and ŷ=0.99: loss ≈ −log(0.99) ≈ 0.01. Nearly correct → small penalty.
  • If y=1 and ŷ=0.01: loss ≈ −log(0.01) ≈ 4.6. Confidently wrong → huge penalty.
  • This asymmetric penalization (compared to MSE) is what makes it the right loss for probability outputs.

Multiclass Extension

For K classes, use the softmax function instead of sigmoid:

P(y=k | x) = exp(zₖ) / Σⱼ exp(zⱼ)  // outputs sum to 1 across all classes
Loss: Categorical Cross-Entropy = −Σₖ yₖ log(ŷₖ)
Implementation Pointers
  • Logistic regression has no hyperparameters by default (besides regularization strength C = 1/λ). Great baseline for any classification problem.
  • Use class_weight='balanced' in sklearn when dealing with class imbalance — it re-weights the loss contribution of each class inversely proportional to its frequency.
  • Coefficients are log-odds: exp(wᵢ) gives the odds ratio for feature i — interpretable and useful for communicating results.
  • Logistic regression with L1 regularization does automatic feature selection (some weights go to exactly 0).
  • Always check the calibration of probability outputs. A model that outputs 0.7 should be right 70% of the time on those samples.

Module 06 / Supervised Learning

Decision Trees & Ensembles

From simple if-else trees to the most powerful tabular ML algorithms: Random Forests and Gradient Boosting.

Decision Trees

A tree recursively partitions the feature space by asking binary questions (e.g., "Is x₂ > 3.5?") and assigns a prediction to each leaf. Training = finding the optimal sequence of splits.

How to choose splits?

Splitting Criteria
  • Gini Impurity (classification): G = 1 − Σₖ pₖ². Measures how often a random element would be misclassified. 0 = pure node (all one class). Pick the split that maximally reduces Gini.
  • Information Gain / Entropy (classification): H = −Σₖ pₖ log(pₖ). Split that maximizes the decrease in entropy. Slightly prefers splits that produce balanced partitions.
  • MSE reduction (regression): Split that maximizes reduction in mean squared error within each resulting node.

Trees are greedy — they pick the best split at each step locally, not globally optimal. This is fast but not perfect.

Core Problem: Trees Overfit Aggressively
  • A fully grown tree memorizes training data — each leaf can contain just 1 sample. Perfect train accuracy, terrible generalization.
  • Fix: limit max_depth, require min_samples_split, or prune after building.
  • Trees are high variance — slightly different training data → completely different tree structure.

Random Forests — Bagging + Feature Subsampling

Train N trees, each on a bootstrap sample (random sample with replacement) of the training data, and at each split, only consider a random subset of features. Aggregate predictions by majority vote (classification) or averaging (regression).

Why This Works
  • Bagging reduces variance: Individual trees are high-variance. Averaging many uncorrelated trees cancels out their errors.
  • Feature subsampling decorrelates trees: Without it, all trees would pick the same dominant features → correlated → averaging doesn't help much.
  • Out-of-bag (OOB) error: each tree is trained on ~63% of data. The remaining 37% can be used as a free validation set — no separate val split needed.

Gradient Boosting — The Tabular ML Champion

Instead of training trees in parallel (like RF), boost sequentially. Each new tree is trained to predict the residual errors of all previous trees. The final model is an additive sum of trees:

F(x) = f₁(x) + f₂(x) + ... + fₙ(x)
// fₜ is trained on residuals of F_{t-1}
// Equivalently: each tree fits the negative gradient of the loss
Gradient Boosting Implementation Pointers (XGBoost/LightGBM)
  • Key hyperparameters: n_estimators (more = lower bias but risk overfit), learning_rate (shrinks each tree's contribution), max_depth (3–6 is typical), subsample, colsample_bytree.
  • XGBoost and LightGBM are the state-of-the-art for structured/tabular data. For most Kaggle competitions on tabular data, one of these wins.
  • Use early stopping with a validation set — stop adding trees when val loss stops improving. Makes n_estimators less critical to tune.
  • Feature importance is built-in — useful for interpretability and feature selection.
  • Unlike neural nets, tree-based models are largely robust to feature scaling. You don't need to normalize inputs.

Support Vector Machines

Elegant geometric intuition — find the decision boundary that has maximum margin from both classes.

The Core Idea

For a linearly separable binary classification problem, infinitely many hyperplanes can separate the classes. SVM finds the one that maximizes the margin — the gap between the nearest points of each class (called support vectors) and the boundary.

Key Geometric Concepts
  • Decision boundary: The hyperplane wᵀx + b = 0
  • Margin: Distance between the two margin hyperplanes (wᵀx + b = ±1). Width = 2/‖w‖.
  • Maximizing margin = minimizing ‖w‖ = a constrained quadratic optimization problem.
  • Support vectors: The training points that lie on the margin boundaries. Only these determine the decision boundary — the rest are irrelevant. This is what makes SVMs memory-efficient and robust.

Soft Margin (Handling Non-Separable Data)

Real data is rarely perfectly separable. The soft margin SVM introduces slack variables ξᵢ that allow some points to violate the margin, controlled by hyperparameter C:

min ½‖w‖² + C·Σξᵢ
// C controls the tradeoff: large C = smaller margin, fewer violations (risk overfitting)
// small C = larger margin, more violations allowed (risk underfitting)

The Kernel Trick — Non-Linear Decision Boundaries

SVM is fundamentally linear. But you can implicitly map data into a higher-dimensional feature space where it becomes linearly separable — without ever explicitly computing the transformation. This is done via kernel functions:

K(x, x') = φ(x)ᵀφ(x')  // dot product in high-dim space, computed cheaply in original space
KernelFormulaWhen to use
Linearxᵀx'Linearly separable; high-dimensional data (text)
RBF / Gaussianexp(−γ‖x−x'‖²)Default choice; captures complex boundaries
Polynomial(xᵀx' + r)^dWhen interactions between features matter
Implementation Pointers
  • SVMs are sensitive to feature scaling — always standardize inputs before using SVM.
  • Two key hyperparameters: C (regularization) and γ (RBF kernel width). Tune together via grid search on log scale.
  • SVMs don't scale well: training is O(n² to n³) in number of samples. Avoid for n > ~100,000. Use LinearSVC or SGDClassifier instead for large datasets.
  • SVMs don't natively output probabilities. sklearn's probability=True uses Platt scaling (fits a logistic regression on top) — expensive and slightly inaccurate.
  • SVMs work well in high-dimensional spaces with few samples (e.g., text classification, genomics).

Neural Networks

Universal function approximators that learn hierarchical representations. The foundation of modern AI.

The Basic Unit: A Neuron

A single neuron computes a weighted sum of its inputs, then applies a non-linear activation function:

output = activation(w₁x₁ + w₂x₂ + ... + wₙxₙ + b)
// Without activation, stacking layers = still just one linear transformation
// Non-linearity is what gives neural nets their power

Architecture

Layers
  • Input layer: Raw features. No computation — just the data dimensionality.
  • Hidden layers: Intermediate representations. "Deep" = multiple hidden layers. Each layer learns increasingly abstract features.
  • Output layer: Final prediction. Linear for regression; sigmoid for binary classification; softmax for multiclass.

Activation Functions — Why They Matter

ActivationFormulaKey PropertyWhen to use
ReLUmax(0, z)Non-saturating; sparse activationDefault for hidden layers in nearly all modern nets
Sigmoid1/(1+e⁻ᶻ)Saturates at 0 and 1 → vanishing gradientsOutput layer for binary classification only
Softmaxexp(zₖ)/Σexp(zⱼ)Outputs sum to 1 across classesOutput layer for multiclass
LeakyReLUmax(0.01z, z)Prevents dying ReLUWhen ReLU causes dead neurons
tanh(eᶻ−e⁻ᶻ)/(eᶻ+e⁻ᶻ)Zero-centered; still saturatesRNNs; largely replaced by ReLU in FF nets
The Dying ReLU Problem
  • ReLU outputs 0 for any negative input. If a neuron's weights get updated such that it always receives negative input, it permanently outputs 0 and its gradient is always 0 — it "dies".
  • Fix: Leaky ReLU (small slope for negatives), or GELU (used in transformers).

Forward Pass & Backpropagation

→
Forward pass: Compute activations layer by layer from input to output. Compute the loss at the end.
←
Backward pass (backprop): Apply the chain rule of calculus to compute ∂L/∂w for every weight in the network, propagating gradients from output layer back to input layer.
↑
Parameter update: Use computed gradients + optimizer (Adam, SGD) to update all weights simultaneously.
Chain rule: ∂L/∂w₁ = (∂L/∂a₂) · (∂a₂/∂z₂) · (∂z₂/∂a₁) · (∂a₁/∂z₁) · (∂z₁/∂w₁)
// Gradients multiply through each layer. Many layers = many multiplications → vanishing/exploding

Universal Approximation Theorem

A feedforward network with a single hidden layer of sufficient width can approximate any continuous function on a compact subset of Rⁿ to arbitrary precision. This is an existence result — it doesn't tell you how to find the weights or how many neurons you need. In practice, depth (more layers) is far more efficient than width for learning complex functions.

Neural Net Implementation Pointers
  • Weight initialization matters: Don't initialize all weights to 0 (symmetry — all neurons learn the same thing). Use He initialization (for ReLU) or Xavier/Glorot (for tanh/sigmoid).
  • Batch normalization: Normalize activations between layers. Dramatically stabilizes training, allows larger learning rates, reduces dependence on initialization.
  • Start small: Begin with 1–2 hidden layers. Add depth/width only if train loss is still high. More parameters = more regularization needed.
  • Dropout: Randomly zero p% of neurons per batch during training. Strong regularizer for fully-connected layers. Don't use on batch-normalized layers — it interferes.
  • Frameworks: PyTorch (research standard, dynamic graph) or Keras/TensorFlow (production, more static). Both auto-differentiate — you only write the forward pass.

Module 09 / Unsupervised Learning

Clustering — K-Means

Finding structure in unlabeled data by grouping similar points together.

What is Clustering?

Given unlabeled data points, assign each to a cluster such that points within the same cluster are more similar to each other than to points in other clusters. No ground truth — the algorithm discovers structure.

K-Means Algorithm

1
Initialize: Randomly place K centroids in the feature space (or use K-Means++ for smarter initialization).
2
Assign: For each data point, find the nearest centroid. Assign the point to that cluster.
3
Update: Recompute each centroid as the mean of all points assigned to it.
4
Repeat: Steps 2–3 until assignments stop changing (convergence). Guaranteed to converge, but to a local minimum.
Objective: minimize J = Σᵢ Σₓ∈Cᵢ ‖x − μᵢ‖²
// Sum of squared distances from each point to its cluster centroid
// Also called "inertia". Lower = tighter clusters.
Choosing K — The Elbow Method
  • Run K-Means for K = 1, 2, 3, ..., N. Plot inertia vs K.
  • As K increases, inertia always decreases. Look for the "elbow" — the K where inertia stops decreasing sharply. That's the natural number of clusters.
  • Silhouette score is a more rigorous measure: how similar a point is to its own cluster vs neighboring clusters. Range [−1, 1]. Pick K that maximizes average silhouette score.

K-Means Limitations

When K-Means Fails
  • Assumes spherical clusters of similar size. Will split elongated or irregularly shaped clusters incorrectly.
  • Sensitive to initialization: Can converge to bad local minima. Fix: run multiple times with different random seeds, keep best result (n_init=10 in sklearn).
  • Sensitive to outliers: Outliers skew centroid positions because the mean is non-robust. Consider removing outliers first, or using K-Medoids instead.
  • You must specify K upfront — not always obvious. Domain knowledge or elbow/silhouette methods help.

Other Clustering Algorithms (Quick Reference)

AlgorithmMechanismWhen to use
DBSCANDensity-based. Points in dense regions form clusters; sparse points = noise/outliers.Irregularly shaped clusters; needs to detect outliers; don't know K.
HierarchicalBuilds a dendrogram by iteratively merging/splitting clusters.When you want to visualize cluster hierarchy. Can choose cut at any level.
Gaussian MixtureProbabilistic: assigns soft cluster membership via EM algorithm.Overlapping clusters; need probability of cluster membership; elliptical clusters.
Implementation Pointers
  • Always standardize features before clustering — K-Means uses Euclidean distance, so features on different scales dominate unfairly.
  • K-Means doesn't work well with high-dimensional data (curse of dimensionality — distances become meaningless). Apply PCA first to reduce dimensions.
  • DBSCAN's two hyperparameters: ε (neighborhood radius) and min_samples (minimum points to form a core point). Use a k-distance plot to choose ε.

Module 10 / Unsupervised Learning

Dimensionality Reduction

High-dimensional data is sparse, hard to visualize, and kills distance-based algorithms. Learn to compress it intelligently.

The Curse of Dimensionality

As dimensions increase, the volume of space grows exponentially. Data becomes increasingly sparse — any fixed dataset has fewer and fewer points per unit volume. Distances between points converge (everything is "far" from everything else), making nearest-neighbor search and clustering meaningless. Models need exponentially more data to generalize in high dimensions.

Principal Component Analysis (PCA)

PCA finds the directions of maximum variance in the data and projects onto those directions. The k principal components (PCs) are orthogonal vectors — the first PC explains the most variance, the second the next most, etc.

1
Standardize the data (zero mean, unit variance per feature). Critical — PCA is sensitive to scale.
2
Compute covariance matrix C = XᵀX / (m−1). This captures how features vary together.
3
Eigen-decomposition: Find eigenvalues (λ) and eigenvectors (v) of C. Each eigenvector is a principal component direction.
4
Sort by eigenvalue (descending). Eigenvalue = variance explained by that PC. Keep top k PCs.
5
Project: Z = XV_k where V_k = matrix of top k eigenvectors. Data is now in a k-dimensional space.
Choosing k — Explained Variance Ratio
  • Explained variance ratio of PC i = λᵢ / Σλⱼ
  • Cumulative explained variance: plot cumulative sum. Pick k where it exceeds your threshold (e.g., 95%).
  • Alternatively: keep all PCs with eigenvalue > 1 (Kaiser criterion).
What PCA Actually Does
  • PCA is a linear transformation. It rotates the coordinate system to align axes with directions of maximum variance.
  • It preserves global structure (large-scale variance) but may lose local structure (subtle clusters).
  • PCA components are linear combinations of original features — still interpretable (unlike UMAP/t-SNE).
  • Reconstruction is possible (inverse transform) — useful for compression or de-noising.

t-SNE and UMAP — For Visualization

PCA is great for preprocessing and compression. For 2D/3D visualization of high-dimensional data, non-linear methods are better at preserving local structure:

MethodSpeedPreservesUse for
t-SNESlow O(n²)Local structure (clusters)Visualizing clusters; exploratory analysis
UMAPFastLocal + some globalLarge datasets; better general alternative to t-SNE
Critical: Don't Trust t-SNE/UMAP for Quantitative Analysis
  • Distances in t-SNE space are meaningless. Two clusters appearing close does not mean they are similar.
  • Cluster sizes in t-SNE are meaningless — all clusters are rendered at similar scale regardless of actual density.
  • t-SNE/UMAP are stochastic — different runs give different layouts. Use multiple runs and perplexity/n_neighbors settings.
  • Never use t-SNE/UMAP outputs as features for downstream ML — use PCA instead.
Implementation Pointers
  • Always standardize before PCA. PCA maximizes variance — unscaled features with large ranges dominate.
  • For sparse data (e.g., text TF-IDF matrices), use Truncated SVD (also called LSA) — equivalent to PCA but works on sparse matrices without centering.
  • PCA before K-Means or SVM is a common and effective preprocessing step for high-dimensional data.

Model Evaluation Metrics

Choosing the wrong metric is choosing the wrong objective. This is the step most beginners rush and most experts obsess over.

Regression Metrics

Classification — The Confusion Matrix

Confusion Matrix (Binary Classification)
  • TP (True Positive): Predicted positive, actually positive. Correct.
  • TN (True Negative): Predicted negative, actually negative. Correct.
  • FP (False Positive / Type I Error): Predicted positive, actually negative. "False alarm."
  • FN (False Negative / Type II Error): Predicted negative, actually positive. "Miss."
MetricFormulaWhen to use
Accuracy(TP+TN)/(TP+TN+FP+FN)Only when classes are balanced. Misleading on imbalanced data.
PrecisionTP/(TP+FP)When FPs are costly (spam filter: don't mark real email as spam).
Recall (Sensitivity)TP/(TP+FN)When FNs are costly (cancer screening: don't miss a tumor).
F1 Score2·(P·R)/(P+R)Harmonic mean of precision and recall. Use when you need balance.
AUC-ROCArea under ROC curveThreshold-independent. Measures separability. 0.5 = random, 1.0 = perfect.
PR-AUCArea under Precision-Recall curveBetter than AUC-ROC for highly imbalanced datasets.
Precision vs Recall — The Fundamental Tradeoff
  • Lowering the classification threshold → more positives predicted → higher recall, lower precision.
  • Raising the threshold → fewer positives predicted → lower recall, higher precision.
  • The ROC curve plots TPR vs FPR at every threshold. AUC summarizes this into one number.
  • Ask: Is a false positive or a false negative more expensive in your domain? That determines which metric to optimize.

Cross-Validation

Single train/val splits are noisy — you might get lucky or unlucky with your split. k-fold CV averages performance across k different splits for a more reliable estimate:

1
Split data into k equal folds (typically k=5 or k=10).
2
For each fold: train on the other k−1 folds, evaluate on this fold.
3
Average the k evaluation scores. This is your CV score ± standard deviation.
Evaluation Best Practices
  • Report metric ± standard deviation over CV folds, not just the mean. High variance → your estimate is unreliable.
  • Always define your metric before training, based on business requirements. Don't retrofit the metric to what your model does well.
  • For time-series: use time-based splits, not random k-fold. Future data must never be in the training fold.
  • Stratified k-fold preserves class proportions in each fold — essential for imbalanced classification.
  • Statistical significance: if model A has CV score 0.82 ± 0.03 and model B has 0.84 ± 0.04, the difference may not be statistically significant. Use paired t-tests or McNemar's test for rigorous comparison.
